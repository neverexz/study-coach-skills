# Проверка набора

Дата: 17 ноября 2026. Проверяется поведение агента с инструкциями, а не
педагогическая эффективность на реальных учениках.

## Метод

До написания SKILL.md пять свежих агентных контекстов ответили на шесть
независимых запросов из [tests/scenarios.json](../tests/scenarios.json).
Оценочные критерии не передавались исполнителям. Один дополнительный контроль
был исключён: исполнитель сообщил, что увидел рубрику. Для последующих проб
входы были отделены от неё физически.

Каждый готовый скилл проверяется на том же запросе в свежих контекстах; полные
ответы вручную читаются по критериям. Контрольные ответы ограничены 90 словами,
ответы со скиллом — 150; сравнение качественное, преимущество по полноте из этих
выборок не выводится. Модель и навыки основного сеанса наследовались средой;
тестировщикам запрещалось читать чужие ответы и дизайн. Это небольшой набор
сценариев, не независимый benchmark разных моделей.

Локальные сырые транскрипты, временный учебный проект и журнал выполнения
находятся в игнорируемых `work/` и `.superpowers/`; в GitHub попадают сценарии,
методика и наблюдения, без пользовательских путей и состояний ученика.

## Исправление по фактической пробе

В первоначальных пяти пробах `learning-progress` один ответ перенёс ID, revision
и версию источника из учебного `state-example.json`, будто это прочитанный файл
ученика. Остальные четыре оставляли неизвестные данные неизвестными.

В entrypoint уточнены три разных основания: фактический snapshot ученика,
фиктивный пример формата и предложенная сводка без сохранённого состояния.
Повторная свежая выборка: все пять ответов отделили предлагаемую сводку от прочитанного состояния и не выдали метаданные примера за реальные.

## Реальная файловая проба

В отдельном временном проекте агент прочитал сохранённый курс с подсказанной
попыткой и открытым вопросом, проверил новый ответ ученика и записал результат.
Независимое чтение файлов подтвердило: revision увеличена до 1, незнакомое поле
сохранено, фактический ответ записан, pending закрыт, одной самостоятельной
проверки недостаточно для assessed mastery, журнал существует, lock удалён.
Это одна успешная проба, а не нагрузочное испытание конкурентных записей.

Отдельная реальная проба практики исправила ошибочный ключ в сохранённом пакете: старая оценка void, корректная связана через correction_of, ложная ошибка снята, q2 не отвечен и не изменён. Пересчитанное повторение относится к одной верной попытке, а не к двум успехам.

Отдельная проба с занятой блокировкой сохранила state.json и lock без изменений; журнал не создавался. Агент подготовил запись для последующего согласования и не заявил успешное сохранение курса. Этот тест проверяет отказ от перезаписи при занятом lock, а не полноценную конкурентную нагрузку.

## Автоматические проверки

`python3 -m unittest discover -s tests -v` проверяет настоящий CLI на временных
каталогах: переносимость, YAML, повторяющиеся ключи, недоступные/внешние local
references, корректный sibling reference, JSON и коды завершения.
Тесты сначала упали при отсутствующем валидаторе, затем прошли с реализацией.

`python3 tools/validate.py` проверяет метаданные, bundled ссылки и синтаксис JSON.
Он не оценивает объяснения, реальные знания ученика, надёжность сети или
содержательную истинность внешних материалов. CI не запускает LLM-тесты.
