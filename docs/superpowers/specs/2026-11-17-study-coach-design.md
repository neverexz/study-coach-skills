# Study Coach: единый вход в учебный набор

Статус: пользователь одобрил реализацию 17 ноября 2026.
Дата: 17 ноября 2026.

## Задача

Пользователь хочет обращаться к одному мастер-скиллу вместо запоминания и
переключения шести имён. Предлагается новый `study-coach`, использующий уже
реализованные учебные сценарии и общий контракт прогресса.

## Подходы

1. Оставить текущий набор: Codex может выбирать скиллы автоматически по их
   description, а пользователь — явно вызывать любой из них. Это уже доступный
   способ работы, но общие правила переключения режимов не собраны в одном входе.
2. Добавить `study-coach` — рекомендация автора. Один понятный вход и явные
   правила передачи контекста; цена — дополнительный небольшой пакет и проверки
   его маршрутизации. Пользователь подтвердил этот вариант.

Основание для автоматического выбора: [официальная документация Codex](https://learn.chatgpt.com/docs/build-skills#how-codex-uses-skills).

## Поведение мастера

- `$study-coach Хочу освоить SQL по этим материалам` запускает нужный учебный
  сценарий. Дальше можно писать обычные просьбы: объяснить, дать подсказку,
  потренироваться, исследовать вопрос, показать прогресс или продолжить.
- По текущему намерению выбирается один ведущий режим: курс → `mastery-tutor`,
  выбранный материал → `source-study`, задача → `guided-solve`, упражнения/проверка/
  спорная оценка → `adaptive-practice`, исследование → `learning-research`.
- Сохранение и возобновление используют `learning-progress`. Для «продолжим»
  сначала восстанавливается выбранный курс; если курсов несколько, уточняется нужный.
- Агент читает инструкции выбранного сценария и нужные references. Мастер
  маршрутизирует работу; он не подразумевает отдельный API вызова скиллов.
- При смене режима сохраняются существующие ID, pending-задачи, неотвеченные
  элементы группы, позиция чтения и отметки о помощи. Побочный вопрос не означает
  отказ от текущего задания. Явный запрос ученика имеет приоритет над предлагаемым шагом.
- Один фактический ответ остаётся одной попыткой. В рамках шага назначается один
  ответственный за оценку и одно сохранение общего результата через существующий
  контракт. Подсказка или готовое решение остаются assisted при возврате в курс.
- Существенные результаты сохраняются для выбранного курса с проверкой записи.
  Если записи нет, выдаётся переносимая сводка; будущая фоновая работа не обещается.
- Если нужного пакета нет, сообщается конкретная недоступная возможность; можно
  помочь в пределах имеющихся инструкций, сохраняя прогресс provisional там, где
  общий контракт отсутствует. Успешный вызов несуществующего скилла не выдумывается.

## Границы

Все шесть текущих скиллов сохраняют самостоятельные точки входа. Мастер использует
их правила вместо копирования учебных циклов и не создаёт параллельную схему
состояния, собственные пороги освоения или новый планировщик повторений. Создание
учебников, отдельный runtime, глобальная установка и публикация не входят.

## Реализация и проверка

Создать `skills/study-coach/SKILL.md`; подробную матрицу маршрутизации вынести в
reference только при необходимости. Обновить README, публичные сценарии и текущий
счёт пакетов. Общий валидатор уже обнаруживает пакеты динамически.

Проверить обычные запросы всех шести направлений и три перехода: побочный вопрос
после частичного ответа на группу; подсказка внутри курса с последующим ответом;
исправление ключа после возобновления. Дополнительно проверить отсутствующий
сценарий, неоднозначное «продолжим» и сохранение одного ответа без дублирования.
Использовать свежие baseline/guided контексты и структурную валидацию.

Имена, небольшой формат маршрутизации и тестовые fixtures выбирает исполнитель.
Общий state/evidence контракт сохраняется, а изменения за пределами маршрутизации
выносятся отдельно. Результат — локальный коммит в текущей ветке, без push.
