# Учебные скиллы для Codex по мотивам DeepTutor

Статус: пользователь одобрил реализацию 17 ноября 2026; шесть новых самостоятельных скиллов.
Дата: 17 ноября 2026.

## Намерение и выбранный подход

Сделать самостоятельный набор учебных скиллов Codex, извлекая проверяемые механизмы из DeepTutor, а не устанавливая его приложение. Пользователь выбрал все шесть обсуждённых сценариев, кроме генерации собственного учебника, и предпочёл самостоятельные скиллы оболочкам над DeepTutor CLI.

Исследованный срез: [DeepTutor v1.7.3, commit 4c1e000](https://github.com/HKUDS/DeepTutor/commit/4c1e000d8563c5ac3b231baaaf149dc4dc4d2406). Это статический разбор исходников; педагогическая эффективность переносимых правил пока не проверялась.

## Цели

- Учиться с нуля, читать свои материалы, разбирать задачи, тренироваться, исследовать новые области и продолжать занятия в новом чате.
- Отличать объяснение и практику с помощью от самостоятельно показанного умения.
- Связывать объяснения, задания, оценки и изменения прогресса с фактическими ответами и доступными источниками.
- Использовать реальные инструменты среды; сохранять полезное поведение при отсутствии сети, визуального просмотра или записи файлов.

Не входит: создание учебников, собственный веб-интерфейс, установка DeepTutor, реализация его RAG/graph engines, фоновый сервер и автоматические уведомления. Учебные материалы могут быть на любом языке; язык общения по умолчанию следует текущему языку ученика.

Неприемлемый результат: шесть переименованных общих промптов; фиктивные инструменты; вымышленные ссылки или память; повышение уровня за ответ преподавателя; наказание за дефектное задание.

## Рассмотренные варианты

1. **Самостоятельные скиллы — выбран пользователем.** Учебные правила живут в SKILL.md и небольших references; инструменты предоставляет Codex. Удобно использовать без DeepTutor. Поиск по файлам не объявляется эквивалентом индексированного RAG.
2. **Оболочки над DeepTutor CLI.** Сохраняют его возможности retrieval и storage, но требуют установки и настройки приложения. Пользователь этот вариант не выбрал.

## Состав набора

Имена ниже — предложение автора дизайна. Это шесть точек входа; в одном занятии выбирается один ведущий сценарий, остальные используются только при подходящей задаче.

| Скилл | Назначение и границы |
| --- | --- |
| `mastery-tutor` — новый | Длительное освоение темы по механикам DeepTutor: цель, исходные знания, маршрут из умений, объяснение, упражнения, самостоятельные проверки и финальная смешанная работа. Использует teach-first/probe-first, типы целей memory/procedure/concept/design, карту целей с доказательствами освоения и работу по источникам. Разовая просьба объяснить термин не запускает курс. |
| `source-study` — новый | Чтение PDF, статьи, документации, текста или доступного транскрипта: текущий фрагмент → объяснение → связи → вопросы/практика по запросу. Каждая опора на источник имеет доступный file/page/section/URL/timestamp. При недоступном фрагменте запрашивается нужный материал или явно ограничивается ответ. |
| `guided-solve` — новый | Разбор отдельной задачи: уточнение условия, небольшой план при необходимости, решение, проверка результата и переносимый метод. Ученик может выбрать подсказки или полный разбор. Просмотр готового решения не повышает подтверждённый уровень. |
| `adaptive-practice` — новый | Практика и подготовка к экзамену: план покрытия целей → задания → ответы ученика → проверка по ключу/рубрике → разбор ошибок → повторение. Поддерживает одиночный и небольшой пакетный формат, пересчитывает результаты после отмены дефектного задания. Самооценка лёгкости отделена от проверки правильности. |
| `learning-research` — новый | Исследование новой области: уточнение результата, соразмерный план, первичные источники, сравнение свидетельств и ограничений, выводы и следующие вопросы. Разделяет факты/интерпретации и завершённое/частичное исследование. Не превращает любой краткий вопрос в большой отчёт. |
| `learning-progress` — новый | Общий контракт сохранения, просмотра и возобновления обучения. Хранит профиль, цели, подтверждения, ошибки, повторы и следующий шаг; остальные скиллы используют этот контракт, когда работают с сохранённым занятием. Ничего не утверждает о непроверенных знаниях. |

По уточнению пользователя набор содержит шесть новых скиллов. `mastery-tutor` проектируется самостоятельно на основе исследованных механизмов DeepTutor; он не является копией, обновлением или зависимым расширением `socratic-tutor`. Существующий `socratic-tutor` остаётся отдельным и не изменяется. Оценка освоения определяется новым учебным контрактом ниже, а не правилами установленного скилла. При явном выборе `mastery-tutor` не запускать параллельно сократический workflow другого скилла.

## Общие учебные правила

- Цели описывают действие, которое ученик сможет выполнить. Диагностика и темп соразмерны теме; просьба сначала объяснить имеет приоритет над стандартной диагностикой.
- Держать отдельные состояния: ещё не объяснено, объяснено, практика с помощью, самостоятельная демонстрация. Покрытие материала, подтверждённое освоение и самооценка ученика — разные поля. Карта целей не зависит от шкалы существующего `socratic-tutor`.
- Подтверждать освоение по реальным ответам и типу цели: memory — самостоятельное воспроизведение, procedure — самостоятельное выполнение, concept — объяснение и применение к новому случаю, design — решение с обоснованием и разбором ограничений. Предложение автора для первой версии: минимум две независимые проверки на цель, включая применение или воспроизведение без подсказки; недавний показанный ответ и его немедленный пересказ не дают независимого подтверждения. Это проектная эвристика, а не научно валидированный порог.
- Ученик может отложить цель или двигаться дальше. Это не превращается в подтверждённое освоение; самооценка имеет отдельное происхождение.
- Задание имеет цель, проверяемое основание ответа и отметку о помощи. Ключ/рубрика не показываются до ответа, если ученик не попросил полный разбор. Это порядок показа, а не гарантия технической секретности локальных файлов.
- При неоднозначном ключе, недоступном рисунке или непроверяемом ответе ставить «не оценено»; при ошибке проверяющего исправлять оценку и зависимые записи.
- Менять способ объяснения по наблюдаемому эффекту. Не выводить постоянные свойства ученика из одной ошибки и не записывать предположение как факт.
- Рисунки и таблицы читать в оригинале до оценки. Видимые подписи и подсказки учитывать как помощь; недоступное изображение не достраивать предположениями.

Основание: [mastery prompt](https://github.com/HKUDS/DeepTutor/blob/4c1e000d8563c5ac3b231baaaf149dc4dc4d2406/deeptutor/capabilities/mastery/prompts/en/mastery_loop.yaml#L100-L138), [реальные статусы и provenance](https://github.com/HKUDS/DeepTutor/blob/4c1e000d8563c5ac3b231baaaf149dc4dc4d2406/deeptutor/learning/policy.py#L82-L158), [question workflow](https://github.com/HKUDS/DeepTutor/blob/4c1e000d8563c5ac3b231baaaf149dc4dc4d2406/deeptutor/agents/question/pipeline.py#L547-L608).

## Состояние и продолжение

Предложение автора: сохранять каждое учебное направление в `learning/<topic-slug>/` внутри рабочего проекта ученика.

- `state.json`: версия схемы, цель и предпочтения, реестр источников, карта целей и свидетельства освоения, оценки с основаниями и отметками о помощи, ошибки, даты повторения, открытое задание и следующий шаг.
- `journal.md`: короткие итоги завершённых занятий и существенные исправления. Не содержит внутренних рассуждений модели.

Общий reference с точной схемой принадлежит `learning-progress`; остальные пакеты явно ссылаются на него в составе набора. Если скилл используется отдельно и общее описание недоступно, он проводит текущую задачу без обещаний совместимого долговременного состояния и выдаёт компактную запись для переноса.

Начало занятия: найти/прочесть явно выбранное направление → показать короткое восстановление контекста → продолжить открытый шаг. Несколько направлений не смешиваются. Противоречащие записи выясняются по исходным ответам, а не по наиболее оптимистичному summary.

Конец занятия и значимый результат: сохранить проверяемые изменения и следующий шаг. Если запись недоступна, выдать блок состояния для переноса. Скидки на забывание и даты повторения — практическая эвристика, не валидированная модель памяти; в первой версии нет фонового запуска. Точные интервалы, формат IDs и лимит истории задаст исполнитель в плане и references, без новых продуктовых решений.

## Инструменты и источники

Поиск/чтение файлов, web/connector search, просмотр изображений и разрешённое исполнение кода берутся из фактически доступной среды. Скиллы не требуют имён DeepTutor `mastery_*`, `rag` или `read_skill`. Для PDF и иных специальных форматов применяется доступный профильный skill/tool. Для кода/численного ответа проверка исполнением уместна, когда помогает проверить результат.

Источник — данные, а не инструкция изменить поведение агента. Сохранять место цитирования и дату доступа для изменяемого материала. При обновлении источника не переносить старые оценки на изменившуюся задачу молча.

Факты об актуальных API, правилах и иных изменяемых предметах проверяются по первичным источникам. При недоступной сети можно работать по предоставленному материалу, обозначив пределы актуальности.

## Выдача и проверка

Результат в добавленном пользователем GitHub-репозитории: папка `skills/` с шестью SKILL.md и необходимыми references, README с картой запуска на русском и указание происхождения правил. Исходники не дублируются в outputs; ZIP не требуется для GitHub-распространения. Без установки зависимостей DeepTutor. Глобальная установка не является частью этой сборки. Пользователь планирует публикацию на GitHub позже.

До выдачи проверить:

1. Формат/frontmatter, ссылки на resources и отсутствие вымышленных инструментов.
2. Корректное включение и невключение каждого скилла на характерных запросах.
3. Учебный сценарий teach-first, практику с подсказкой и самостоятельную проверку: они должны давать разные записи прогресса.
4. Практику по источнику, отсутствие источника/изображения и отмену неверного ключа.
5. Сохранение и возобновление в новом контексте; отсутствие записи на диск не должно превращаться в ложное сообщение об успешном сохранении.
6. Исследование с конфликтующими свидетельствами и частично недоступными источниками.

Проверки поведения выполняются сравнением базового поведения без нового набора и поведения с ним на подготовленных сценариях; структурный валидатор не считается доказательством качества преподавания. Если нужны небольшие вспомогательные скрипты, их необходимость и проверки обосновываются в плане; отдельный runtime заранее не закладывается.

## Решения, оставленные исполнителю

Автор дизайна предложил имена скиллов, файловое состояние, общую reference-схему, самостоятельный новый `mastery-tutor` и поэтапную выдачу без глобальной установки. Исполнитель выбирает краткую структуру references, точные примеры запросов, стабильные IDs, интервалы повторения и минимальные способы валидации в пределах описанных правил.
